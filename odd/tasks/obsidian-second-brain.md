# Obsidian second brain
Objective: connect Kairo, Claude Code and Codex to an Obsidian vault as a two-way memory vault for our models. Branch: feat/obsidian-second-brain. Delivery strategy: stacked-to-main (user chosen). Test runner: node --test; full suite via npm test (package.json:39, `node --test 'test/**/*.js' 'test/**/*.mjs' 'test/**/*.cjs'`).

## Specs
- S1 (user, verbatim): "necesitamos conectar a kairo,claude,codex, etc a obsidian para poder tener un segundo cerebro pro asi decirlo"
- S2 (user chose, verbatim): "Dos vías: además, los agentes leen tus notas de Obsidian como contexto, por ejemplo vía MCP. Así lo que escribís a mano también les llega a ellos."
- S3 (user, verbatim): "al final del dia, debe ser util para nuestros modelos, por que es debera de ser nuestro vault de \"recuerdos\" por asi decirlo"
- S4 Vault layout, by owner (approved by user with "ok dale"): agents write ONLY under the vault folder Kairo/ (existing KAIRO_VAULT_SUBDIR). Inside Kairo/: kind-first folders from existing KAIRO_VIEW_KINDS (projects, decisions, architecture, sessions, reviews), each note carries a project: frontmatter field, one hub note per project at Kairo/projects/<project>.md, a generated index Kairo/Home.md, and a bounded Kairo/hot.md. The human's folders stay free-form; agents only read them. .obsidian, .kairo-backups, .trash and secret-looking files are never read nor written. Notes link with wikilinks so the Obsidian graph shows relations.
- S5 Write path (approved plan): wire the existing publisher (src/global/observability/obsidian-*.js) to CLI commands kairo obsidian status and kairo obsidian publish. Vault path is explicitly configured, never guessed (existing rule in obsidian-status.js). Publish is a dry run unless confirmed (existing hasConsent). Add hash-guarded writes: refuse to update a note whose SHA-256 changed since it was last published by Kairo, even if it carries kairo_kind. Never delete notes, never touch .obsidian. Data source: official `engram export FILE --project P` JSON, curated to decisions, architecture and bugfix observations, plus read-only `graphify-out/GRAPH_REPORT.md` from the project directory.
- S6 Read path (approved plan): add read-only tools to the existing kairo MCP server (src/global/mcp/kairo-mcp.js) so Claude, Codex and Kairo share one channel: vault_search (query, optional project/kind filters, bounded results with path, title, frontmatter, snippet, sha256) and vault_read (one note by vault-relative path, bounded size, returns content plus sha256). Reads cover the whole vault (human notes and Kairo/ notes) with realpath containment, symlink-escape refusal, and the S4 exclusions. Output is compact and model-friendly.
- S7 Hot context (approved plan): publish also regenerates Kairo/hot.md, a bounded summary of the most relevant recent memory per project; expose it through a vault_hot MCP tool. Automatic injection into sessions is opt-in and off by default, because injected vault text goes to the model provider.
- S8 Engram stays the authority for agent memory and Graphify for code structure; the vault mirrors them for humans and adds the human's own notes. Borrowed ideas only from github.com/AgriciDaniel/claude-obsidian (hash-guarded writes, opt-in hot context); no fork, no dependency, no Python.
