# Team formation integrity
Objective: Kairo forms and routes a two-provider team that respects role classes, never waits or silently drops a provider, and uses every capable tier. Branch: feat/team-formation-integrity (worktree agentic-harness-worktrees/team-formation-integrity).
Delivery strategy: stacked-to-main (user selected; parent owns git). Test runner: npm test (node --test); exact package.json script: `node --test 'test/**/*.js' 'test/**/*.mjs' 'test/**/*.cjs'`.

- S3 (approved 2026-10-30, L-b): Role classes: analysis, coordination, labor, verification. Frontier (thinking) models only in analysis, coordination or verification roles; never routine labor. Frontier status comes from AA capability evidence, never from price: a model is frontier when its comparable AA intelligence evidence is in the upper quartile of a fixed, versioned reference pool independent of live quota; role qualification uses role-weighted AA component percentiles plus existing absolute role floors. One shared compatibility predicate for formation, reform and runtime routing. Earlier approval quote retained: "ok dale".
- S4 (approved 2026-10-30, L-b): Default catalog of 11 roles in cells. Global: Master Orchestrator (the user session, outside Kairo selection, read-only). Design cell: Technical Lead (analysis, read-only; merges Architect, Planner, Debugger diagnosis), Explorer (labor, read-only). Implementation cell: Execution Coordinator (coordination, read-only, never writes code; splits work, assigns edit surfaces, resolves integration), Builder (labor, writes; merges Builder, Backend Builder, Frontend Builder, Debugger fix, Refactorer; specialties become skills), Documenter (labor, docs only). Quality cell, independent of implementation: Quality Lead (verification, read-only; merges Verifier and Test Designer), Reviewer (analysis, read-only), Security Reviewer (analysis, read-only), Test/Repro Runner (labor, scratch writes only; renames Test Runner). Delivery: Deliverer (labor, authorized delivery only; absorbs DevOps delivery duties). Cells and workers activate on demand, not always on; Builder B only for independent work. RDD review-* and jd-judge-* stay protocol actors, not staffing slots. Old role IDs keep working through aliases and migration of persisted strategies and catalogs; changed assignments of an approved team require explicit re-approval, never silent change. Earlier approval quote retained: "ok dale".
- S4a (clarified and approved 2026-10-30): Diagnosis belongs to the analysis lead; the transitional Debugger (fix) executes its bounded handoff using the existing Builder execution qualification contract. No model-name exemption, guaranteed Haiku assignment, global floor reduction or full T6 role migration is authorized by this clarification.
- S5 Reviewer and Security Reviewer are always from a different provider than every Builder when both providers are configured; no silent same-provider degradation. If impossible, formation fails loudly with the reason instead of approving. With two providers, all Builders of an approved team use one provider and review uses the other; if impossible, approval blocks with the reason.
- S6 Never wait while a compatible model on another provider is admissible: runtime routing considers every authorized compatible alternative before WAIT and keeps a per-candidate rejection trace. Entitlement handling runs before substitution.
- S7 Expired Claude entitlements (7-day TTL) re-probe automatically or fail loudly; a provider never disappears silently. Add CLI kairo team verify-access [--refresh] wrapping the existing service.verifyClaudeEntitlements.

- S11 Explanations tell the truth: real cost source instead of the boilerplate "unknown cost ranks last", precise exclusion stage instead of "outside_band", and kairo team plan shows the underlying error instead of plan_failed.
