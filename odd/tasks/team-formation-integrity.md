# Team formation integrity
Objective: Kairo forms and routes a two-provider team that respects role classes, never waits or silently drops a provider, and uses every capable tier. Branch: feat/team-formation-integrity (worktree agentic-harness-worktrees/team-formation-integrity).
Delivery strategy: stacked-to-main (user selected; parent owns git). Test runner: npm test (node --test); exact package.json script: `node --test 'test/**/*.js' 'test/**/*.mjs' 'test/**/*.cjs'`.

- S3 (approved 2026-10-30, L-b): Role classes: analysis, coordination, labor, verification. Frontier (thinking) models only in analysis, coordination or verification roles; never routine labor. Frontier status comes from AA capability evidence, never from price: a model is frontier when its comparable AA intelligence evidence is in the upper quartile of a fixed, versioned reference pool independent of live quota; role qualification uses role-weighted AA component percentiles plus existing absolute role floors. One shared compatibility predicate for formation, reform and runtime routing. Earlier approval quote retained: "ok dale".
- S4 (approved 2026-10-30, L-b): Default catalog of 11 roles in cells. Global: Master Orchestrator (the user session, outside Kairo selection, read-only). Design cell: Technical Lead (analysis, read-only; merges Architect, Planner, Debugger diagnosis), Explorer (labor, read-only). Implementation cell: Execution Coordinator (coordination, read-only, never writes code; splits work, assigns edit surfaces, resolves integration), Builder (labor, writes; merges Builder, Backend Builder, Frontend Builder, Debugger fix, Refactorer; specialties become skills), Documenter (labor, docs only). Quality cell, independent of implementation: Quality Lead (verification, read-only; merges Verifier and Test Designer), Reviewer (analysis, read-only), Security Reviewer (analysis, read-only), Test/Repro Runner (labor, scratch writes only; renames Test Runner). Delivery: Deliverer (labor, authorized delivery only; absorbs DevOps delivery duties). Cells and workers activate on demand, not always on; Builder B only for independent work. RDD review-* and jd-judge-* stay protocol actors, not staffing slots. Old role IDs keep working through aliases and migration of persisted strategies and catalogs; changed assignments of an approved team require explicit re-approval, never silent change. Earlier approval quote retained: "ok dale".
- S4a (clarified and approved 2026-10-30): Diagnosis belongs to the analysis lead; the transitional Debugger (fix) executes its bounded handoff using the existing Builder execution qualification contract. Debugger (diagnosis) retains its own demanding analysis requirements and read-only permissions. Workers do not inherit the leader's reasoning requirement/floor or borrow its score. No model-name exemption, guaranteed Haiku assignment, global floor reduction or full T6 role migration is authorized by this clarification.
- S5 Reviewer and Security Reviewer are always from a different provider than every Builder when both providers are configured; no silent same-provider degradation. If impossible, formation fails loudly with the reason instead of approving. With two providers, all Builders of an approved team use one provider and review uses the other; if impossible, approval blocks with the reason.
- S6 Never wait while a compatible model on another provider is admissible: runtime routing considers every authorized compatible alternative before WAIT and keeps a per-candidate rejection trace. Entitlement handling runs before substitution.
- S7 Expired Claude entitlements (7-day TTL) re-probe automatically or fail loudly; a provider never disappears silently. Add CLI kairo team verify-access [--refresh] wrapping the existing service.verifyClaudeEntitlements.
- S8 Formation uses every capable tier: a per-model role cap that binds, and pool qualification and final formation share one preprocessing and comparability path (the Planner case excluding qualifying Sonnet .5757 above the .55 floor is a regression test).
- S9 Measured success blends with public capability instead of replacing it, and benchmark coverage differences are visible in decisions; no invented benchmarks, no silently lowered floors.
- S10 With scarce Claude quota, S3 and S5 still hold: cross-provider review uses the cheapest qualified Claude model and only at risk points (high-risk commits), not every task.
- S11 Explanations tell the truth: real cost source instead of the boilerplate "unknown cost ranks last", precise exclusion stage instead of "outside_band", and kairo team plan shows the underlying error instead of plan_failed.
- S12 (approved 2026-10-30, L-b) (user, verbatim): "Three orchestration levels: the general orchestrator (user's session) only orchestrates; role orchestrators (frontier models in analysis roles) decide and delegate; workers (cheap labor models) do search, research, build, test and delivery. Analysis roles consult CodeGraph, Engram, Graphify and Obsidian first and delegate broad reading to a cheap worker instead of reading code themselves." Three levels max (master orchestrator, cell leads, workers); delegation contracts carry goal, authorized files, preserved contracts, decisions taken, acceptance checks, work budget and escalation condition; workers return diff, evidence, blockers; a stuck worker escalates the decision, not the implementation, to a frontier model; implementation can never approve its own quality.
- S13 (approved 2026-10-30, L-b): Kairo derives cells and roles per project, generically, not special-cased to this repo: it analyzes the project (work areas, change history by area and type, recurring work types, risk surfaces) and proposes which cells, roles and skills that project needs, creating extra cells, teams or roles when the analysis needs them, and dropping seats no work maps to. The proposal is shown to the user for approval with the evidence.
- S14 (approved 2026-10-30, L-b): Quota-aware automatic model switching is always on: within each role, Kairo switches among qualified models and providers automatically as quotas rise or fall (5h and weekly windows), keeping S3 and S5; selection ranks qualified candidates by available quota and observed quota per accepted task; API price only informs API cost, never qualification.
- S15 (approved 2026-10-30, L-b): Unpriced models are eligible on capability with cost marked unknown; AA-unmatched models stay visible with a capability_unverified warning and may qualify only through validated local role probes; no provider disappears silently, no invented scores, no lowered floors. Remove the below-floor price peer rescue (contradicts S9).
- S16 (approved 2026-11-02): Kairo decides reasoning effort per delegation from role, task risk and remaining quota (for example low for Test/Repro Runner and Explorer, medium for Builder, high only for high-risk review), returns it in kairo team route, and lowers effort before downgrading the model when quota tightens. No hardcoded effort outside Kairo.
- S17 (approved 2026-11-02): Host wrappers and agents execute exactly the provider, model and effort returned by kairo team route; no hardcoded model or effort in wrappers. The orchestrator and the Execution Coordinator cannot write files on any host (Claude, Codex and others): the no-write rule is enforced by Kairo core, not only by the Claude Code plugin.
